# Examples

Synthetic worked examples for the SORT4CIRC DPP implementation profile.

Synthetic example. Not SORT4CIRC project data.

Everything here is invented. Identifiers use the reserved `urn:example:` and
`https://example.org/` namespaces, dates are fictional, and no value describes any
organisation's real activity, materials, processes or performance.

The one exception is the Annex G worked example, which keeps its published
`urn:sort4circ:` identifiers and `TXHO-WP3-B01-001` sample label so that this repository
reproduces the published reference record exactly. Those values are synthetic too.

## `worked_example.py`

The end-to-end Tier 1 and Tier 2 loop, in-process and offline:

~~~sh
python examples/worked_example.py
~~~

It validates a synthetic passport, creates it through the API, commissions a data carrier,
resolves the carrier identifier back to the passport, appends a lifecycle event and a
material observation, drains the local integrity worker and verifies the resulting digest.
No external service or hardware is contacted.

Read it alongside [Getting started](../docs/getting-started.md) — it is short, and it is
the fastest way to see the intended request sequence.

## `fixtures/`

Four positive and ten negative fixtures. Thirteen are generated by
`SyntheticFixtureFactory` ([`src/sort4circ_dpp/synthetic.py`](../src/sort4circ_dpp/synthetic.py));
its deterministic values make tests reproducible, and it derives nothing from any source
record. The fourteenth, `valid-annex-g-garment.json`, is maintained by hand because it
reproduces the published Annex G worked example (see `fixtures/README.md` for its
provenance).

| Fixture | Demonstrates |
| --- | --- |
| [`valid-minimum.json`](fixtures/valid-minimum.json) | The smallest complete record |
| [`valid-annex-g-garment.json`](fixtures/valid-annex-g-garment.json) | The Annex G worked example: a knitted upper-body garment with a laboratory-determined composition |
| [`valid-two-technologies-disagree.json`](fixtures/valid-two-technologies-disagree.json) | Conflicting observation sets, correctly retained rather than merged |
| [`valid-uncharacterised-garment.json`](fixtures/valid-uncharacterised-garment.json) | Nothing measured, stated honestly |
| `invalid-*.json` (ten) | One profile rule violated per file |

Negative fixtures carry a test-only `$expect` member naming the reason code they must
produce. The fixture runner strips it before validating; the CLI does not, so validate them
through the runner:

~~~sh
python tools/validate_fixtures.py     # -> 14/14 fixtures behaved as declared
~~~

If you are implementing this profile in another language, these fourteen files plus the
digest vectors in `tests/test_canonical.py` are your first conformance corpus. See
[Conformance](../docs/conformance.md).
